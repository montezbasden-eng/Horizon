## [OpenAI retracts three AI-generated mathematical proofs](https://twitter.com/danintheory/status/2108065033070789090) ⭐️ 8.0/10

OpenAI has withdrawn three mathematical results from its public math repository, as documented in the project's history file on GitHub. The retraction follows scrutiny of proofs that were reportedly generated by AI, some of which lacked Lean formal verification. This incident raises serious questions about the reliability of AI-generated mathematical proofs and the adequacy of current verification practices, potentially undermining trust in AI's role in advancing mathematics. It also highlights the need for rigorous formal verification standards as AI systems increasingly contribute to research-level mathematics. The retracted results were among hundreds of claimed breakthroughs, and not all of them had Lean certificates; even Lean-verified proofs can encode unintended statements if the formalization is flawed. The sheer volume of AI-generated proofs makes comprehensive human review impractical, meaning errors may persist undetected for years.

**Background**: Lean is an interactive theorem prover that allows mathematicians to write proofs in a formal language that a computer can check step by step, providing a high level of certainty. OpenAI has recently used AI models to generate mathematical proofs at scale, some of which are verified in Lean while others are written in natural language. The retraction underscores the challenges of ensuring correctness when AI produces mathematics faster than humans can review it.

## [$2800 rig with 8x Radeon Pro V620 runs Qwen3.8-Flash-Next via custom vLLM fork](https://www.reddit.com/r/LocalLLaMA/comments/1x0wnz1/2800_rig_with_8x_radeon_pro_v620_256_gb_vram/) ⭐️ 8.0/10

A Reddit user built a roughly $2800 rig using eight AMD Radeon Pro V620 GPUs (32 GB VRAM each, 256 GB total) and created a custom vLLM fork with hand-tuned RDNA2 kernels to run Qwen3.8-Flash-Next, achieving 60-100 tokens/s decode and over 3000 tokens/s prefill. The user reports this is roughly 800% faster than llama.cpp on the same hardware, which previously managed only 350-450 tokens/s prefill. This demonstrates that older, relatively cheap enterprise GPUs can be repurposed into a high-performance local LLM inference rig, potentially lowering the cost barrier for running large models with big VRAM requirements. It also shows how custom kernel work can unlock hardware that mainstream inference frameworks like vLLM do not officially support. The setup uses pipeline parallelism (PP=4, no tensor parallelism) with routed experts quantized to W4A16 while other weights remain BF16, and MTP (multi-token prediction) with 3-token drafting boosts decode to 60-100 t/s versus 40-50 t/s with MTP disabled. The user notes the cards are no longer available at $350 each, and the RTX 4090 visible in the setup is only used for image/video generation, not LLMs.

reddit · r/LocalLLaMA · /u/_TheWolfOfWalmart_ · Oct 8, 17:12

**Background**: The Radeon Pro V620 is an older RDNA2-based enterprise GPU originally designed for cloud gaming and data center workloads, featuring 32 GB of VRAM per card. vLLM is a popular open-source inference engine optimized for high-throughput serving of large language models, but it primarily targets NVIDIA GPUs and newer AMD architectures, leaving older RDNA2 cards without official support. Qwen3.8-Flash-Next is a recent large language model from the Qwen family, and running it locally typically requires substantial VRAM and optimized inference software.

## [LemonSeed runs Qwen3.8-27B on iPad with external AMD R9700 GPU](https://www.reddit.com/r/LocalLLaMA/comments/1x18e95/qwen3827b_159_toks_on_r9700_64_toks_on_strix_halo/) ⭐️ 8.0/10

LemonSeed Studio demonstrated running Qwen3.8-27B (Q4) at 158.5 tok/s on an AMD R9700 GPU attached to an iPad Pro via Thunderbolt, using its portable LemonSeed Engine (LSE) that embeds the unmodified upstream Linux amdgpu/amdkfd driver as a PCIDriverKit extension. The same engine also hit 159.4 tok/s on macOS and 64.4 tok/s on Strix Halo (Radeon 8060S) under Linux, with version 0.5.8 adding DFlash2 draft trees by default and working Strix Halo prefill/decode. This is a notable proof that a single portable inference engine can deliver near-identical performance across Linux, macOS, and iPadOS on the same AMD GPU, and that an iPad can drive an external GPU for local LLM inference. It matters for the LocalLLaMA community because it expands hardware options for on-device inference and shows that upstream Linux GPU drivers can be reused on Apple platforms via PCIDriverKit. LSE records the model's forward pass as a graph, fuses ops, and auto-tunes kernels per device, while speculative decoding (MTP and DFlash2) dynamically picks how many draft tokens to verify based on measured acceptance and cost. Decode numbers for Qwen3.8-27B Q4 (baseline / MTP=3 / DFlash2 tok/s) were 31.2 / 108.7 / 158.5 on iPadOS, 32.2 / 111.9 / 159.4 on macOS, 32.0 / 111.0 / 144.6 on Linux, and 14.0 / 47.8 / 64.4 on Strix Halo; 4K prefill reached 1,636 (iPadOS), 1,634 (macOS), 1,418 (Linux R9700), and 517 (Strix Halo).

reddit · r/LocalLLaMA · /u/TheOriginalG2 · Oct 9, 01:20

**Background**: PCIDriverKit is Apple's framework for writing user-space PCI device drivers as DriverKit extensions, which allows a driver to talk to hardware like a Thunderbolt-attached GPU without kernel modifications. The amdgpu and amdkfd drivers are the upstream Linux kernel components for AMD graphics and compute, and amdkfd provides the HSA compute interface used by GPU inference runtimes. Speculative decoding is a technique where a smaller draft model proposes several future tokens that the target model verifies in parallel, and MTP (Multi-Token Prediction) and DFlash2 are specific draft mechanisms used here to boost throughput.
